# OpenSEO parity

AgenticSEO brings the SEO capabilities of [OpenSEO](https://github.com/every-app/open-seo) to local commands and agent skills. This page tracks that parity row by row, for contributors and for anyone comparing the two. Users should start with the [README](../README.md).

## Inventory

Baseline: OpenSEO commit `0ffff93101043aad7600a3b6a499a0cd2887ef49`; paths are relative to it. The inventory covers OpenSEO's registered MCP tools **and** its SEO-related application server functions and services, grouping related operations into one row. The linked upstream sources define each row's required behavior. A row is `verified` when a local command covers the operations, inputs and result distinctions of those sources, with fixture tests, live evidence and a read-back for every mutation. Paths are representative, not exhaustive: `scripts/upstream-coverage.mjs` lists upstream modules this file never names, so a review can judge them instead of relying on memory.

Every row was verified on 2026-09-24. A fresh project ran every command against live DataForSEO, Search Console and GA4 data, each mutation was read back and each export file checked; `scripts/live-check.mjs` repeats that pass. Each workflow skill ran once in Pi on real data. The evidence column lists each row's deliberate local changes.

## Out of scope

These OpenSEO features belong to its hosted Web product and have no local equivalent:
- hosted public report links (`src/serverFunctions/reports.ts` `shareReport`/`unshareReport`); a report's HTML page can be shared as a file, which is not the same as a public link;
- workspace and organization permissions (`src/serverFunctions/workspace.ts`, `src/serverFunctions/organization.ts`);
- subscriptions and credits (`src/serverFunctions/billing.ts`); DataForSEO bills you directly;
- onboarding and activation widgets (`src/serverFunctions/onboarding.ts`, `src/server/features/activation`);
- the in-app SAM chat (`src/serverFunctions/sam.ts`, `src/serverFunctions/samAccess.ts`, `src/server/features/sam`); its SEO workflows are the skills your own agent runs;
- hosted account identity (`src/server/mcp/tools/whoami.ts`) and app plumbing (`src/serverFunctions/config.ts`, `src/serverFunctions/middleware.ts`).

## Verifying a row

A row stays `verified` when a local invocation produces OpenSEO's comparable result for a fixture or an authorized live project, keeps the distinctions that matter (target scope, market, dates, source and missing data), and leaves inspectable evidence in the project. A mutation must read back on a second invocation. A new upstream capability is added as a row before it is built. Pi is the only agent client verified so far.
